Git config command
The Git config command is used to set the values to identify 
who made changes to Git repositories. To set the values of user.email 
and user.name to your email and name, type: 

: ~$ git config  - -global user.email “
me@example.com
”
: ~$ git config  - -global user.name “My name”


Git directory and working tree

The git directory contains all the changes and their history 
and the working tree contains the current versions of the files.

Files start as untracked and must be added to the staging area 
using git add to be included in the next commit.

Modified stage awaits staging.
Staging area is the section awaiting commit.
Committed files are snapshots added into the repository.



//Skipping the staging area or add stage 
git commit -a -m "commit message"

git diff
git diff --staged
git add -p
Removing files and renaming files in a repository
git rm <file>
git mv <old> <new_file>



//Undoing changes before commiting 
git checkout: undo unstaged changes
git reset HEAD <file>: used to undo staged changes 
git reset -p: to choose the part you want to reset
git add *: is used to add modified files in the working tree

//amend commit 
git commit --amend 

Avoid amending commits that has been made public



//Rollbacks 
git revert HEAD: used to undo changes in the recent commit 
git revert <ID>: used to rollback a specific commit using it's 
ID that shows after you display the log of commits


//identifying commits
Commits are identified using their ids which are the hashed 40 character
codes known as the SHA1 used to guarentee the consistency of the repositories
